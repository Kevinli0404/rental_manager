# 產品規格

## 名稱

| 項目 | 名稱 |
|---|---|
| 中文名稱 | 租賃管理平台 |
| 英文名稱 | Rental Management Platform |
| App 顯示名稱 | Rental Manager |
| 專案、套件名稱 | `rental_manager` |

「租賃管理平台」是長期的名稱。第一版只做點交；其他功能（例如租約、租金紀錄）之後再評估。這份文件沒列到的功能都不要先做。

## 一句話

房東和房客在入住、退租時，用手機逐項檢查房屋狀況、拍照、雙方簽名；退租時對照入住紀錄，現場產生 PDF 點交單。

## 使用情境

- 點交在空屋現場進行，網路常常不穩，所以所有功能都要能離線使用。
- 主要在手機上使用（直式）。平板能正常操作就好，不另外設計版面。
- 第一版只在單一裝置上使用，不用登入，資料只存在裝置上。

## 第一版範圍（純本機）

要做：
- 物件：新增、編輯、刪除（名稱、地址、備註）
- 點交紀錄：每個物件可以有多筆，類型為「入住」或「退租」
- 點交填寫：依空間逐項記錄狀況、備註、照片；同一類空間可以有多個（例如兩間臥室）
- 退租對照入住：退租時顯示入住時的狀況，標出變差的項目
- 簽名：房東、房客各簽一次，簽完紀錄鎖定
- PDF：產生點交單，可以預覽、分享、列印
- 設定：預設房東姓名

不做（留給之後的版本）：
- 登入、雲端同步、多人協作（第二階段接 Supabase）
- 使用者自訂範本
- 押金計算、水電錶讀數

## 名詞

| 名詞 | 說明 |
|---|---|
| 物件 | 一間出租的房子 |
| 點交紀錄 | 某個物件某一次入住或退租的檢查 |
| 範本 | 定義有哪些空間類型、每類空間要檢查哪些項目 |
| 空間 | 客廳、廚房、浴室、臥室等；同一類可以有多個，例如「臥室」「臥室 2」 |
| 空間配置 | 某筆點交紀錄實際有哪些空間和項目；從範本或入住紀錄複製而來 |
| 項目 | 空間裡要檢查的東西，例如牆面、地板、燈具 |
| 狀況 | 每個項目的檢查結果 |

## 轉跳規則

1. 路由照「物件 > 點交 > 簽名」巢狀排列，按返回時依路徑一層層往上。
2. 新增點交不另開頁面：在物件詳情用底部選單選類型和日期（預設今天）。房東姓名帶入設定裡的預設值，房客姓名可以先空著。建立草稿後直接進點交頁。退租怎麼建立，見「退租對照入住」。
3. 點交頁只有一頁，依狀態決定能不能編輯。
4. 填寫時每次變更都立即寫入資料庫，沒有「儲存」按鈕，離開頁面也不詢問。
5. 按「簽名」時先做簽名前檢查（見下方規則）。沒通過就切到該空間、捲到第一個沒通過的項目並提示，不進簽名頁。
6. 兩個簽名都完成後，狀態改為已簽名，跳到 PDF 頁。在 PDF 頁按返回，回到唯讀的點交頁。
7. 列表資料一有變動就自動更新，不需要手動重新整理。

## 點交頁版面（手機）

- 上方是可以左右滑動的空間分頁，每個分頁列出該空間的項目。
- 每個項目可以選狀況、填備註、拍照。
- 底部固定顯示填寫進度和「簽名」按鈕。
- 右上角選單有「管理空間」。

## 空間

- 建立點交時，依範本或入住紀錄產生空間配置（見「範本」「退租對照入住」）。
- 草稿時可以：新增空間（從範本的空間類型選）、複製空間、改名稱、刪除空間。
- 新增或複製同一類空間時自動編號：臥室、臥室 2、臥室 3。
- 複製空間只複製項目，不複製狀況、備註和照片。
- 刪除空間時，如果底下已經有填寫內容或照片，要先確認；內容和照片一起刪除。
- 至少要保留一個空間。

## 點交紀錄狀態

| 狀態 | 可以做什麼 |
|---|---|
| 草稿 | 編輯所有欄位、管理空間、拍照、刪除照片、刪除紀錄 |
| 已簽名 | 只能檢視和產生 PDF，不能修改 |

已簽名不能退回草稿。

## 項目狀況

| 狀況 | 規則 |
|---|---|
| 良好 | |
| 損壞 | 必須有照片或備註 |
| 缺少 | 必須有照片或備註 |
| 不適用 | 這間房子沒有這個項目 |

- 項目一開始沒有狀況（未填）。
- 嚴重程度：良好 < 損壞 < 缺少。「不適用」不參與比較。

## 退租對照入住

- 建立退租點交時，找同一個物件最近一次「已簽名」的入住紀錄（依點交日期；同一天就取簽名時間較晚的）。
  - 找得到：整份沿用那筆入住的空間配置（空間和項目都一樣），並記下對照的是哪一筆。
  - 找不到：依範本建立，並提示「沒有已簽名的入住紀錄，這次不做對照」。
- 退租的狀況、備註、照片一律從空白開始，不複製入住的內容。
- 點交頁的每個項目下方，顯示入住時的狀況和備註；入住有照片時可以點開查看。
- 退租的狀況比入住嚴重時，標示為「變差」。
- 沿用自入住的空間在退租時不能刪除，沒有的項目改選「不適用」；退租時新增的空間標示「入住時沒有」。

## 簽名前檢查

- 至少有一個空間。
- 每個項目都選了狀況。
- 狀況是「損壞」或「缺少」的項目，至少有一張照片或填了備註。
- 房東和房客姓名都有填。

## 刪除規則

- 刪除一律是軟刪除（標記刪除時間），畫面上不再顯示。
- 草稿：確認一次就刪除。
- 已簽名：要二次確認才刪除。
- 已經被退租紀錄拿來對照的入住紀錄不能刪除。
- 刪除物件時，底下的點交紀錄一起刪除。

## 範本

- 第一版只有內建範本，放在 `assets/templates/`。範本定義有哪些空間類型、每類空間有哪些項目。
- 建立入住點交（或找不到入住紀錄的退租點交）時，依範本產生空間配置並存進點交紀錄。之後範本改版，不影響已經建立的紀錄。
- 依範本產生時，每類空間各產生一個，順序同範本；同一類要第二個（例如「臥室 2」）時，再用「管理空間」新增。
- 內建範本「一般住宅」的空間：玄關、客廳、廚房、浴室、臥室、陽台。各空間的項目見 `assets/templates/default_residence.json`。

## PDF 點交單內容

1. 物件名稱、地址；點交類型、日期；房東、房客姓名
2. 依空間列出每個項目的狀況和備註
3. 有照片的項目附上縮圖
4. 退租時另外列出「與入住差異」：變差的項目（空間、項目、入住狀況 → 退租狀況、備註）
5. 房東、房客的簽名和簽名時間

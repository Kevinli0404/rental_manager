# 開發計畫

進度都更新在這份文件：做完的項目打勾，順序有變就直接調整。

## 第一階段：本機版 MVP

### T0 建立專案
- [x] 在 `rental_manager` 資料夾裡執行 `fvm flutter create --project-name rental_manager --org <自己的 org> .`；org 用自己的網域或 GitHub 帳號，不要用公司的
- [x] 用 fvm 釘住 Flutter 版本（`.fvmrc`）
- [x] App 顯示名稱設為「Rental Manager」（iOS 的 `CFBundleDisplayName`、Android 的 `android:label`）
- [x] lint 設定（`analysis_options.yaml`），`fvm flutter analyze` 0 issue
- [x] 建立資料夾結構（見 `architecture.md`）
- [x] GitHub Actions：每次 push 跑 analyze 和 test
- [x] README 初版，包含「我怎麼使用 AI」一段

驗收：空白 App 能在模擬器跑起來，主畫面顯示「Rental Manager」，CI 通過。

### T1 資料庫與範本
- [x] 五張資料表和 DAO（物件、點交、項目結果；照片、簽名的 DAO 移到 T4、T5）
- [x] 內建範本 JSON、空間配置的 model 和載入
- [x] DAO 測試、schema 快照

驗收：測試裡能建立物件和點交紀錄、寫入項目結果，再正確讀回來。

### T2 物件
- [x] 物件列表（含空狀態）、新增、編輯、刪除

驗收：新增後回到列表就自動出現；刪除後從列表消失。

### T3 點交填寫
- [x] 物件詳情的點交紀錄列表；用底部選單新增點交（入住、退租都照範本建立，退租對照入住在 T6）
- [x] 刪除草稿點交紀錄（確認一次）
- [x] 點交頁：空間分頁、選狀況、填備註、即時存檔、顯示填寫進度
- [x] 管理空間：新增、複製、改名稱、刪除

驗收：可以有兩間臥室並各自填寫；填到一半把 App 關掉，重開後內容都還在。

### T4 照片
- [ ] 照片的 DAO
- [ ] 拍照、從相簿選取、縮小後存檔
- [ ] 刪除空間前判斷「有沒有內容」時，把照片也算進去（T3 只看狀況和備註）
- [ ] 照片檢視、刪除

驗收：資料庫只存相對路徑；App 更新版本後照片仍然能顯示。

### T5 簽名
- [ ] 簽名的 DAO
- [ ] 修改點交日期、房東和房客姓名
- [ ] 簽名前檢查（規則要有單元測試）
- [ ] 簽名頁；簽完狀態改為已簽名，點交頁變唯讀
- [ ] 刪除已簽名的點交紀錄、刪除底下有已簽名紀錄的物件時，要二次確認

驗收：沒通過檢查時，會切到該空間並捲到第一個有問題的項目；簽完之後不能再修改。

### T6 退租對照入住
- [ ] 建立退租時找最近一次已簽名的入住紀錄，沿用空間配置
- [ ] 點交頁顯示入住時的狀況、備註、照片，標出變差的項目
- [ ] 刪除限制：沿用自入住的空間、被對照的入住紀錄不能刪
- [ ] 規則單元測試（找入住紀錄、判斷變差）

驗收：入住「良好」、退租「損壞」的項目會標示變差；沒有已簽名的入住紀錄時，退租照範本建立並有提示。

### T7 PDF
- [ ] 中文字型、PDF 版面
- [ ] 退租的「與入住差異」段落
- [ ] 預覽、分享、列印

驗收：PDF 的中文正常顯示，包含照片縮圖、簽名，退租時列出差異。

### T8 設定與收尾
- [ ] 設定頁（預設房東姓名）
- [ ] 操作影片、README 截圖

驗收：照著 README 的步驟，可以從零把專案跑起來。
